# Flows

## Discover

### Start

- Visitor opens the portfolio without prior product context.

### Result

- Visitor understands that Farrel is a Product Engineer.
- Visitor understands the type of problems Farrel works on.
- Visitor can access selected work.

## Explore Work

### Start

- Visitor wants evidence of Farrel's work.

### Flow

- Visitor views available projects.
- Visitor selects a project.

### Result

- Selected case study opens.

## Evaluate Case Study

### Start

- Visitor opens a project.

### Result

- Visitor can understand the problem.
- Visitor can understand relevant constraints.
- Visitor can understand Farrel's role and decisions.
- Visitor can understand the resulting solution.
- Visitor can understand available outcomes or impact.

## Learn About Farrel

### Start

- Visitor wants professional context beyond individual projects.

### Result

- Visitor can understand Farrel's Product Engineering focus.
- Visitor can understand relevant experience and working approach.

## Contact

### Start

- Visitor decides to discuss an opportunity, project, or problem.

### Result

- Visitor reaches an available contact channel.
